# 内置能力补齐实施说明

## 1. 目标

在不把确定性控制重新交给低能力模型的前提下，补齐编码、执行、产物、调度和
委派能力。实现遵循：

- 工具由 Runtime 注册，不依赖模型臆造；
- 大目录先经过 Tool Router，每轮只提供少量候选；
- 文件访问限定工作区；
- 修改采用精确匹配、内存预检和原子写入；
- 命令有白名单、超时、环境清理和输出限额；
- Cron、子智能体统一进入持久 Job Worker；
- 所有调用继续写入 RunEvent。

## 2. 能力目录

### 文件系统

`ls`、`glob`、`grep`、`read`、`read_many`、`write`、`edit`、
`multi_edit`、`apply_patch`

### 执行与代码

`shell`、`git_status`、`git_diff`、`git_commit`、`lsp`

`lsp` 的 diagnostics 使用实际语言工具；Python 使用 `py_compile/compileall`，
TypeScript 使用 `npx tsc --noEmit`。定义、引用和符号查询在无语言服务器时降级为
确定性源码搜索，并在返回中明确说明结果来源。

### Web 与浏览器

- 原生 `web_search` 优先调用自托管 SearXNG，未配置或失败时聚合
  DuckDuckGo HTML 与 Bing RSS；结果经过 URL 规范化、倒数排名融合、去重和短期缓存；
- 原生 `web_fetch` 读取公开网页正文，不执行脚本，并对每次重定向重新执行 SSRF 校验；
- Tavily 不再是默认依赖，只作为管理员可选的付费增强；
- 无痕 Chrome/Edge CDP 浏览器提供 open、snapshot、click、type、screenshot、close。

浏览器使用独立运行资料，不读取用户日常浏览器登录数据。初始 URL 和链接跳转都经过
SSRF 校验。

### 产物

- 上传附件继续支持 PDF、DOCX、XLSX、代码文本和图片识别，并作为 Thread 任务资产
  持久化稳定 ID、来源 Turn、哈希和所有者；纯文字澄清回复自动延续同一任务附件；
- 附件原件只读物化到每轮隔离工作区，`attachments.resolved` 与
  `attachments.materialized` 进入统一事件流，断线后可回放；
- `document_inspect` 检查 DOCX 结构和正文指纹；`document_format` 只修改格式属性，
  导出前后强制比较 Word XML 文字签名，内容变化时拒绝产出；
- 原有模板继续生成 DOCX、PPTX、XLSX、Markdown；
- `html_generate` 生成独立 HTML；
- `image_render` 无外部服务生成 SVG；
- `image_generate` 对接 OpenAI Images 兼容端点。

### 后台任务

`CronCreate`、`CronList`、`CronDelete`、`CronSetEnabled`

Cron 使用五字段表达式。调度器不直接执行模型，而是创建普通 Chat Job，复用任务
领取、心跳、取消、日志、失败状态和结果持久化。

### 智能体委派

`spawn_agent`、`resume_agent`、`wait_agent`、`list_agents`、
`interrupt_agent`、`close_agent`

异步子任务复用 Job 表，嵌套深度上限为 3。当前智能体只能调用自身或管理员显式绑定的
子智能体。同步短任务仍可使用 `call_agent__*`。

## 3. 权限边界

- 只有 `root` 能在“内置能力”页面全局启用/停用工具，admin 和普通用户只能查看；
- 只有 `root` 能在 Agent 配置中添加或移除内置工具；实际可用集合为
  `全局启用工具 ∩ Agent 已分配工具`；
- 全局停用立即作用于全部运行，Agent 绑定关系保留，以便重新启用后恢复；
- 工具执行入口会再次校验运行时授权，不能通过伪造工具调用绕过目录过滤；
- `AGENT_WORKSPACE_ROOT` 是文件、Git、LSP、Shell 的唯一根目录；
- 路径解析后再次检查，拒绝 `..`、绝对路径越界和符号链接逃逸；
- Shell 拒绝 `;`、管道、重定向、变量展开、命令替换和解释器内联代码；
- `git_commit` 必须明确列出 paths，不允许隐式 `git add -A`，不提供 push；
- 写入、Shell、提交、浏览器输入、Cron 变更要求 `confirm=true`；
- 审查子智能体通过版本策略禁用所有修改和副作用工具；
- 工具输出统一限长并进入结构化观察，原始错误不会作为最终答复。

## 4. 配置

主要环境变量：

```text
AGENT_WORKSPACE_ROOT
BUILTIN_TOOLS_ENABLED
SHELL_TOOL_ENABLED
SHELL_TIMEOUT_SECONDS
SHELL_OUTPUT_CHARS
BROWSER_TIMEOUT_SECONDS
CRON_SCHEDULER_ENABLED
IMAGE_API_BASE_URL
IMAGE_API_KEY
IMAGE_MODEL
```

完整示例见 `.env.example`。

## 5. 激活与回滚

执行：

```powershell
.\.venv\Scripts\python.exe tools\activate_builtin_capabilities.py
```

脚本会：

1. 创建并挂载 `workspace-engineering` Skill；
2. 创建只读“代码审查子智能体”；
3. 发布新的不可变 Harness 版本；
4. 将 Router 候选限制为 7、单步并行限制为 1；
5. 把工具成功预算提高到 8，以支持“发现—修改—验证”闭环。

回滚时可在管理后台“内置能力”逐项停用，或在 Agent 配置中移除绑定。若要在部署层
整体关闭本地执行能力，设置 `BUILTIN_TOOLS_ENABLED=false`；该环境开关优先级高于
数据库中的 root 配置。
