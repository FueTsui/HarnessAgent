# 核心架构落地说明

本项目的执行内核已按“外层任务编排器 + 内层 Agent Loop + 工具执行边界 + 验证反馈”重构。

## 状态模型

- `Project`：长期工作空间与 Thread 分组。
- `Thread`：一条持续任务工作线，保存标题、归档、置顶、项目归属和上下文摘要。
- `Turn`：一次用户输入到控制权返回的完整周期，保存执行快照、状态和最终输出。
- `Item`：Turn 内的追加式最小事实，包括用户/助手消息、计划、工具调用与结果、审批、验证和生命周期事件。

`Job` 仅作为 Worker 的传输与租约记录，不再代表业务 Run，也不作为会话历史来源。

## 执行模型

运行时不再装载固定宏观 Graph，不存在预定义节点和合法边。`AgentLoopState` 只记录已经发生的事实：

```text
构建上下文
  ↓
模型决定下一步 ──→ 输出最终消息 ──→ 完成门禁
  │                                      │
  └→ 工具请求 → 权限/参数/超时控制 → 观察 ┘
                         ↑               │
                         └──── 修订反馈 ─┘
```

动态计划是 Agent Loop 可选的 `update_plan` 能力，不是执行必经阶段。实时外部证据、工具预算、审批和验证属于外围约束，可改变下一次循环输入，但不构成固定 DAG。

## 持久化与事件

创建聊天任务时，在同一事务内创建 Thread（如不存在）、Turn、用户消息 Item 和队列记录。Worker 领取后更新 Turn 状态；运行时事件持续追加为 Item。最终助手消息先写入 Item，再记录 `turn.completed` 等终态事件。

前端过程面板消费 `runtime.*`、`turn.*`、`loop.*`、`tool.*`、`verification.*` 和 `plan.updated` 事件，不再依赖 `graph.*` 节点。

## 主要实现位置

- `backend/runtime/orchestrator.py`：上下文构建和动态 Agent Loop。
- `backend/runtime/loop.py`：无预制节点的循环状态。
- `backend/runtime/task_store.py`：Thread、Turn、Item 持久化原语。
- `backend/jobs.py`：队列、租约、重试、取消和审批调度。
- `backend/worker.py`：Turn 执行与最终结果持久化。
- `backend/api/chat.py`：Thread/Turn 接口与 Item 过程回放。
