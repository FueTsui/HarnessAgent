# 实时外部证据路由与完成门禁

## 背景

Run ID `dcca7a489bbb4a8596db52b0fe0a20ad` 的目标是复盘昨日 A 股市场表现及资金流入、流出。
该 Run 已绑定 `web_search` / `web_fetch`，但工具路由连续 8 轮只提供或选择工作区文件工具，
最终以 `successful_tool_budget` 停止，并错误答复“工作区没有金融市场数据”。

这不是模型知识不足，也不应通过增加提示词解决。按《Harness Engineering 设计原则》的故障分层，
它属于：

- Tool Router 没有把任务意图转为可执行的工具约束；
- 自由循环把“工具调用成功”误当作“任务取得进展”；
- 验证器只检查文本形式，没有检查完成目标所需的证据类型。

## 设计约束

继续采用“厚 Runtime + 轻模型”的既有方向：

1. 确定性意图由 Rule Engine 识别，不让低能力模型自行判断是否需要联网；
2. Tool Router 只向模型披露当前任务需要的窄工具簇；
3. 时效性外部事实先经过确定性前置节点取得证据，再进入自由 Agent Loop；
4. 完成验证同时检查答复文本和证据工具，不能用无关工具成功数代替；
5. 同类工具重复次数由运行时硬限幅，配置不能让小模型无限放宽；
6. 所有判定写入 RunEvent，保证可观察、可复现和可回归。

## 运行路径

```text
用户目标
  ↓
Rule Engine：识别时效性外部事实
  ↓
证据要求：web_search
  ↓
确定性前置检索（参数模板由 Harness 填充）
  ↓
结构化观察
  ↓
Tool Router：仅披露 web_search / web_fetch
  ↓
单步 Agent Loop
  ↓
完成验证：所需证据工具已成功 + 不得错误声称无法联网
  ↓
最终答复
```

复合任务（例如“联网检索后写入工作区文件”）仍保留通用工具评分，避免把开放式任务硬编码成
单一路径。仅在目标明确依赖实时外部事实、且没有工作区处理意图时启用窄 Web 工具簇。

## 运行时不变量

- 已绑定 `web_search` 的实时/近期外部信息任务，必须先获得一次成功联网检索；
- 已获得联网证据后，答复不能再声称“无法访问实时/联网数据”；
- 小模型同类工具最多连续尝试 3 次，即使 Harness 版本配置了更大的值；
- 精确重复调用继续命中观察缓存，不重复执行；
- 前置检索失败会形成结构化失败观察，由后续循环选择重试、替代或明确降级；
- 工具不存在或未授权时不绕过权限，也不自动扩大 Agent 的能力集合。

## 可观察事件

- `evidence.required`：记录本次目标需要的证据工具和判定原因；
- `tool.called` / `tool.completed`：
  `source=rule_engine_preflight` 表示由确定性前置节点执行；
- `tools.routed`：记录总工具数与实际向模型披露的候选；
- `verification.failed`：记录缺少证据或“已有证据仍错误拒绝”的原因；
- `loop.stopped`：记录工具预算或重复调用等停止原因。

## 回归覆盖

- 原始 A 股问题必须路由到 `web_search`，不得提供 `ls`；
- 天气、行情、新闻等中英文时效性意图保持覆盖；
- Rule Engine 必须在模型决策前执行联网检索；
- 已有联网证据时，错误的“无法访问数据”答复不能通过验证；
- Token、前端、模型协议及完整 Harness 测试集持续通过。
