# 免费联网搜索选型与接入

## 结论

采用分层方案：

1. 主方案：自托管 SearXNG，统一聚合多个搜索源，提供稳定 JSON API；
2. 零配置方案：DuckDuckGo HTML + Bing RSS，服务端并行检索后执行倒数排名融合；
3. 正文获取：独立 `web_fetch`，限制类型和体积，并逐次校验重定向目标；
4. 可选增强：Tavily MCP，由管理员自行启用，不再是系统默认依赖。

## ClawHub 包评估

### multi-search-engine

该包是 OpenClaw Skill，主要指导模型通过 `web_fetch` 直接抓取 16 个搜索网站。
优点是不需要 Token、覆盖中外搜索源；缺点是 HTML 结构不稳定，容易触发
403/429/验证码，而且把引擎选择、重试和结果合并交给模型，不适合低能力模型的
确定性 Harness。

### searxng

该包同样是 OpenClaw Skill，其脚本调用已有的 SearXNG JSON API。包本身不部署
SearXNG，也不是 MCP 服务；需要另行准备 `SEARXNG_URL`。其架构方向正确，但直接
安装不能接入本项目的工具运行时，因此本项目采用原生 Python 客户端实现。

## 配置

不配置任何变量即可使用免费的 DuckDuckGo + Bing 聚合检索。

生产环境建议部署私有 SearXNG，并配置：

```text
SEARXNG_URL=http://127.0.0.1:8080
SSRF_ALLOWLIST=127.0.0.1
WEB_SEARCH_FALLBACK=true
WEB_SEARCH_TIMEOUT_SECONDS=15
WEB_FETCH_MAX_BYTES=2097152
WEB_FETCH_MAX_CHARS=20000
```

SearXNG 的 `settings.yml` 必须在 `search.formats` 中开启 `json`，否则 API 会返回
403。服务只应向本机或可信内网开放，不建议依赖无服务承诺的公共实例。

## 运行时规则

- `web_search` 和 `web_fetch` 均属于 root 管理的内置能力；
- 只有“全局启用且已分配给 Agent”时才会进入工具目录；
- 搜索结果缓存五分钟，减少上游压力；
- 单次最多返回十条结果；
- 免费降级只访问两个稳定入口，不采用 16 站并发抓取；
- 网页正文最大读取 2 MiB、最多向模型返回 20,000 字符；
- 禁止访问环回、私网、链路本地和云元数据地址，除非管理员显式加入白名单。
